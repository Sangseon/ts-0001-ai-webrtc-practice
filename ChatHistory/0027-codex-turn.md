오류 또는 입력 중단 상태를 표시하고 관련 분석 자원을 정리해주세요.

자동으로 다른 장치를 획득하거나 음소거를 해제하지 마세요.

필요한 기능은 다음과 같습니다.

- 마이크 테스트 시작
- 마이크 테스트 종료
- 현재 분석 중인 마이크 표시
- 입력 레벨 바 또는 간단한 시각화
- 필요하다면 상대 레벨 수치
- 테스트 진행 중 상태

- 입력 중단 및 재시도 안내

UI 디자인은 기존 프로젝트 스타일을 유지합니다.

불필요한 차트 라이브러리나 대규모 컴포넌트 개편은 하지 않습니다.

### 8.1. 사용자에게 알릴 내용

입력 레벨 표시가 의미하는 바를 명확히 설명해주세요.

예를 들어 다음 사항을 안내할 수 있습니다.

- 현재 마이크에 입력이 감지되고 있는지 확인하는 기능
- 표시되는 수치는 상대적인 입력 레벨
- 이 표시만으로 실제 상대방에게 음성이 송신되는지 판단할 수 없음
- 마이크 테스트가 회의 음소거를 자동으로 해제하지 않음

테스트를 중단하면 레벨 표시를 초기화하거나 비활성 상태로 변경해주세요.

## 11. 자동화 검증

Step 11의 가상 장치 및 Mock 테스트 환경을 최대한 재사용해주세요.

### 11.1. RMS 계산 단위 테스트

재현 가능한 PCM 샘플을 이용해 다음을 검증해주세요.

- 모든 샘플이 0인 경우 RMS 0
- 일정한 진폭의 샘플에서 예상 RMS
- 더 큰 진폭일수록 RMS 증가
- 양수·음수 진폭에 대한 대칭성
- 입력 크기 또는 비정상 값 방어
- 화면 표시값의 범위 제한

테스트용 임의 숫자를 UI 상태에 주입하는 것만으로 실제 분석 기능을 검증했다고 판단하지 마세요.

계산 로직 검증과 실제 AudioContext 기반 분석 검증을 구분해주세요.

### 11.2. 브라우저 실제 분석

Chrome·Edge에서 가능한 가상 마이크 신호를 사용해주세요.

다음 사항을 검증합니다.

- AudioContext 생성
- MediaStreamAudioSourceNode 연결
- AnalyserNode의 실제 샘플 획득
- 입력 신호에 따른 레벨 변화
- 테스트 시작·종료
- 분석 대상 Track 종료
- 테스트 전용 Track 정리
- 공유 Track 유지

가상 마이크 신호가 일정하다면 무음·발화 간 차이를 검증하기 어렵습니다.

필요하다면 제어된 테스트 신호 또는 Mock Web Audio 입력을 활용하되 실제 브라우저 입력 분석과 구분해 기록해주세요.

### 11.3. 회의 중 독립성

A·B·C가 같은 활성 미디어 회의방에 연결한 상태를 구성합니다.

A가 마이크 테스트를 시작·종료하더라도 다음을 확인해주세요.

- A의 기존 Audio Producer 유지
- B·C의 Consumer 유지
- 미디어 연결 종료 없음
- 다른 참가자의 송수신 변화 없음
- 미터 종료 후 공유 트랙 유지

### 11.4. 음소거 안전성

A가 마이크를 음소거한 상태에서 입력 테스트를 진행합니다.

- 서버 Audio Producer paused 유지
- 클라이언트 통화 Track 비활성 상태 유지
- 원격 Consumer의 상태 유지
- 테스트용 신호가 SFU로 송신되지 않음
- 기존 Audio Producer ID 유지
- 명시적 음소거 해제 전 RTP 재개 없음
- 테스트 종료 후 음소거 상태 유지

테스트 중 레벨이 움직이는 것과 SFU로 오디오가 송신되는 것을 구분해 검증해주세요.

### 11.5. 장치 전환

Step 11에서 구현한 Mock 장치 A/B와 브라우저 가상 장치 환경을 활용해주세요.

- 장치 A를 분석하다 B로 변경
- 실제 분석 대상의 deviceId 또는 Track 참조 변경
- 기존 분석 자원 정리
- 새 분석 대상 레벨 측정
- 늦은 응답으로 이전 장치로 돌아가지 않음
- 전환 실패 시 오류 상태 표시
- 통화 Track 소유권 유지

Mock A/B가 하나의 실제 가상 오디오 소스를 사용하는 경우 서로 다른 물리 마이크의 입력 변화까지 검증했다고 표시하지 마세요.

### 11.6. 반복 및 경합

다음 항목을 포함해주세요.

- 테스트 시작·종료 5회 이상
- 시작 중 종료
- 종료 후 즉시 재시작
- 마이크 변경 중 종료
- 음소거 중 테스트 시작·종료
- 방 전환 중 분석 종료
- 공유 트랙 종료
- 테스트 전용 트랙 중복 획득 방지
- 컴포넌트 해제 후 루프 잔류 방지

자원 수와 실행 상태를 확인해주세요.
