## 5. Chrome·Edge 자동화 브라우저 종료 문제 조사

### 사용자 관찰

해당 창이 자동화가 생성한 Chrome·Edge인지 아직 확정하지 않았습니다.

이전에 자동화 결과에서는 임시 프로필·개발 포트 리스너·mediasoup worker 잔류 0개가 보고됐지만, 실제 Windows 화면에서는 브라우저 창이 남아 있는 것으로 관찰됐습니다.

이 차이의 원인을 조사해주세요.

### 가장 중요한 안전 조건

**자동화가 직접 생성하고 소유한 브라우저 인스턴스만 종료해야 합니다.**

다음은 절대 수행하지 마세요.

- `taskkill /IM chrome.exe`
- `taskkill /IM msedge.exe`
- `taskkill /F /IM node.exe`
- 모든 Chrome·Edge 프로세스 일괄 종료
- 모든 Node.js 프로세스 일괄 종료
- 기존 브라우저 창 전체 종료
- 사용자의 브라우저 프로필 삭제
- 다른 개발 서버나 VS Code 프로세스 종료
- 소유권이 확인되지 않은 과거 잔류 프로세스 강제 종료

사용자가 직접 열어둔 Chrome·Edge와 다른 개발 작업은 반드시 보호해야 합니다.

### 조사할 항목

다음을 기존 자동화 코드에서 확인해주세요.

1. 브라우저를 생성하는 실제 코드 경로
2. Chrome·Edge 실행 방식
3. 브라우저 PID 또는 실행 핸들 관리 방식
4. 브라우저 페이지·컨텍스트 종료 방식
5. 테스트 성공 시 cleanup
6. assertion 실패 시 cleanup
7. timeout 발생 시 cleanup
8. 중간 예외 발생 시 cleanup
9. 자식 프로세스 생성·종료 관계
10. 브라우저 테스트 간 재사용 여부
11. 임시 프로필 생성·삭제 방식
12. 프로세스 종료 코드 및 실제 프로세스 잔류 여부

현재 프로젝트가 어떤 브라우저 자동화 라이브러리 또는 Chrome DevTools Protocol 실행 방식을 사용하는지 실제 코드를 기준으로 확인해주세요.

Playwright·Puppeteer 등의 사용을 가정해서 코드를 변경하지 마세요.

### 정리 방식

가능하면 브라우저 자동화가 제공하는 정상 종료 API를 우선 사용해주세요.

자식 프로세스를 직접 생성한 경우에는 실제 생성한 프로세스 핸들을 이용한 종료를 우선 검토해주세요.

브라우저가 별도 자식 프로세스를 생성하는 구조라면, **해당 자동화 실행에서 생성한 것으로 확인되는 프로세스만** 관리하세요.

Windows 전체 프로세스를 대상으로 프로세스 이름만 비교해 종료하지 마세요.

이미 남아 있는 창은 소유권을 확인하지 못했다면 강제 종료하지 말고 조사 결과에만 기록해주세요.
