# ChatHistory 자동 기록

## 확인한 환경과 공식 지원

2026-10-30 로컬에서 확인한 환경:

- VS Code 확장: `openai.chatgpt` 26.1021.22027 (표시 이름: Codex).
- 확장에 포함된 실행 파일: `codex-cli 0.164.0-alpha.11.1`.
- `codex features list`: `hooks stable true`.
- Node.js: v24.22.1. 외부 패키지를 설치하지 않는다.

[OpenAI 공식 Hooks 문서](https://learn.chatgpt.com/docs/hooks)는 프로젝트의 `.codex/hooks.json`, `UserPromptSubmit.prompt`, `Stop.last_assistant_message`를 지원한다. 프로젝트 설정과 Hook 정의에는 신뢰 승인이 필요하다. 내부 transcript 형식은 안정된 인터페이스가 아니므로 읽지 않는다. 로컬 Hook은 로컬 Codex 실행용이며 클라우드 오케스트레이션에서는 지원되지 않는다.

[공식 설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference)의 `features.hooks`가 활성화 스위치다. 현재 설치본은 이미 활성화되어 있어 사용자 전역 설정을 수정하지 않았다.

위 내용은 공식 기능과 로컬 실행 파일의 확인 결과다. 현재 열려 있는 IDE 대화에서 실제 이벤트가 발생해 파일이 생성되는 것까지 확인한 것은 아니다. 확장이 다른 실행 파일, WSL 또는 원격 런타임을 사용하면 별도 확인이 필요하다.

## 구성과 선택 이유

- `.codex/hooks.json`: 프롬프트 제출과 응답 종료 이벤트에 기록기를 연결한다.
- `scripts/chat-history.cjs`: 기본 Node.js 모듈만 사용한다. API 호출, 추가 확장, 대화 파일 감시 프로세스가 필요 없다.
- `.chat-history/`: 응답 대기 중인 프롬프트, 중복 방지 상태, 잠금 디렉터리를 로컬에 보관한다.
- `ChatHistory/`: 완성된 대화를 Markdown으로 보관하고 GitHub에서 개발 과정 기록으로 관리한다. 새 Markdown 파일은 일반적인 `git add` 대상이다.
- `.gitignore`: 임시 기록기 상태인 `.chat-history/`만 제외한다. `ChatHistory/`는 제외하지 않는다.

Hook 명령은 `node -e`에서 `git rev-parse --show-toplevel`로 현재 작업 디렉터리가 속한 Git 루트를 구하고, 그 아래 `scripts/chat-history.cjs`를 실행한다. 개인 PC의 절대 경로와 셸 전용 경로 치환 문법을 사용하지 않는다. Git 실행 시 표준 입력을 읽지 않게 하며, 기록기 실행에는 표준 입력을 그대로 전달해 Hook JSON을 보존한다. 계산된 경로는 셸 명령 문자열에 삽입하지 않고 Node.js 자식 프로세스의 인자로 전달하므로 공백·한글·특수 문자가 있는 경로도 처리한다.

저장소 이동·Clone 후에도 명령을 바꾸지 않는다. 실행 환경의 PATH에 `git`과 `node`가 있어야 하고 Hook 작업 디렉터리는 해당 Git 저장소 안이어야 한다. Git 메타데이터가 없는 ZIP 사본이나 저장소 밖에서는 경고하고 기록을 건너뛴다. Git 루트 탐색·기록기 실행 실패는 개발을 차단하지 않는다. Windows의 짧은 경로(8.3)와 긴 경로는 `fs.realpathSync.native`로 정규화하여 같은 작업 공간으로 비교한다.

Hook 정의를 변경했으므로 다음 실행 전에 새 정의를 검토하고 신뢰 승인해야 할 수 있다. Windows와 WSL은 각 실행 환경 안에서 Git·Node.js가 동작해야 하며, WSL·macOS·Linux에서의 실행은 이번에 직접 검증하지 않았다.

## 활성화와 실제 동작 확인

1. 저장소 루트에서 터미널로 `node --version`과 `codex --version`을 확인한다. `codex`가 PATH에 없다면 설치된 확장의 `bin/windows-x86_64/codex.exe`를 사용한다.
2. 루트에서 `codex`를 실행한다. 프로젝트 신뢰가 요구되면 저장소와 스크립트를 검토한다. `/hooks`에서 두 Hook의 명령과 내용을 확인하고 신뢰 승인한다. Hook을 변경하면 재검토가 필요할 수 있다. 신뢰 우회 옵션은 사용하지 않는다.
3. VS Code에서 `Developer: Reload Window`를 실행하고, 이 저장소를 작업 디렉터리로 하는 새 로컬 Codex 대화를 연다. 이미 실행 중인 대화에 설정이 소급 적용된다고 가정하지 않는다.
4. 비밀 정보 없는 고유한 문구로 요청한다. 예: `기록 확인용 요청입니다. 최종 답변에 history-check-20261030만 적어주세요.`
5. 응답 완료 후 `ChatHistory/0002-codex-turn.md`를 확인한다. 더 큰 번호가 이미 있으면 그 다음 번호가 생성된다. `User Prompt`와 `Codex Response`를 실제 UI 텍스트와 대조한다. 이 문서의 예시 응답을 실제 응답 대신 저장하지 않는다.
6. 두 번째 요청으로 다음 번호가 생성되고 첫 파일이 바뀌지 않는지 확인한다. `git status --short --untracked-files=all`에 새 기록이 나타나야 한다. `git check-ignore --no-index ChatHistory/0002-codex-turn.md`는 출력 없이 종료 코드 1을 반환해야 한다(제외 규칙 없음). 사용자 전역 Git 제외 규칙이 있다면 별도 확인한다.

공식 문서에서 확실히 확인된 신뢰 관리 방법은 CLI의 `/hooks`다. IDE의 구체적인 승인 UI 위치는 여기서 확인하지 못했다. CLI에서 신뢰 승인해도 IDE의 런타임·설정이 다르면 별도 적용이 필요할 수 있다. 파일이 생성되지 않으면 자동 기록이 활성화되었다고 간주하지 않는다.

## 저장 규칙

- `UserPromptSubmit`에서 받은 `prompt` 문자열을 UTF-8 JSON으로 임시 저장한다. 종료 이벤트가 같은 세션·턴 ID로 도착하면 `last_assistant_message`와 묶는다.
- 받은 문자열을 수정·요약·마스킹하지 않는다. 한글, 공백, CRLF/LF, 코드 펜스를 보존한다. Markdown 구역과 펜스 앞뒤의 구분용 줄바꿈은 원문에 포함되지 않는다. 원문 안의 가장 긴 백틱보다 긴 펜스를 사용한다.
- 같은 턴에 여러 제출 이벤트가 있으면 `Submission 1`, `Submission 2`로 모두 기록한다. 같은 문구를 다시 입력해도 삭제하지 않는다.
- 파일명의 작업명은 자동 기록 시 `codex-turn`으로 고정한다. 프롬프트 내용을 파일명으로 노출하지 않으며 별도 AI 호출도 하지 않기 위한 선택이다. 수동 기록에는 작업명을 지정할 수 있다.
- 기존 번호의 최댓값 다음을 사용한다. 번호 순서는 응답 저장 완료 순서이며 요청 제출 시각순을 보장하지 않는다. 파일 생성은 배타적 생성(`wx`)으로 수행해 기존 파일을 덮어쓰지 않는다.
- 저장된 턴의 반복 `Stop` 이벤트는 중복 기록하지 않는다. 상태 저장 직전 장애가 나면 기록 헤더의 Capture ID로 이미 생성된 파일을 확인한다.
- 프롬프트·최종 응답·세션/턴 ID가 누락되면 경고하고 완성 기록을 생성하지 않는다. 추측하거나 다른 턴의 내용을 가져오지 않는다.
- 민감 정보 패턴이 발견되면 해당 턴 전체의 기록을 보류하고 경고한다. 임의의 마스킹 결과를 원문이라고 기록하지 않는다. 다음 정상 턴의 기록은 계속 진행할 수 있다.

## 민감 정보와 Git

`ChatHistory/`는 **Git 관리 대상**이다. 디렉터리를 통째로 제외하지 않고, 기록 전 검사와 커밋 전 검사 및 사용자 검토로 민감 정보 노출을 줄인다. 기존 기록은 자동으로 수정하거나 덮어쓰지 않는다.

1. 프롬프트에 실제 비밀번호·토큰을 붙여 넣지 않는다. 환경 변수 이름이나 민감 값을 제거한 예제를 사용한다.
2. 자동·수동 기록 전에 비밀번호/API Key/토큰 대입 표현, 일부 제공자 토큰 형식, Bearer 토큰, 개인 키 헤더를 검사한다. 프롬프트·최종 응답·수동 작업명에서 의심 값이 발견되면 해당 턴을 보류한다. 프롬프트 임시 저장 전에도 검사하며, 해당 턴의 임시 상태에는 원문 대신 차단 표시만 남긴다. 저장 성공이나 마스킹된 원문으로 표시하지 않는다. 개발 요청 자체는 차단하지 않는다.
3. 기록 파일을 검토한 뒤 아래 명령을 사용한다. `--check`는 작업 폴더의 Markdown을, `--check-staged`는 실제 커밋 대상인 Git 인덱스의 Markdown을 검사한다. 스테이징 후 작업 파일에서만 비밀을 지운 경우도 인덱스 검사로 감지할 수 있다.

```powershell
node scripts/chat-history.cjs --check
# 사용자가 기록 파일을 검토하고 스테이징한 뒤 실행
node scripts/chat-history.cjs --check-staged
```

결과는 `checked`(검사 파일 수), `suspicious`(의심 파일 수), `failed`(검사 실패 여부)만 출력한다. 민감 원문과 일치 값은 출력하지 않는다. 의심 내용이나 검사 실패가 있으면 종료 코드 1, 통과하면 0이다. `checked: 0`은 검사할 기록이 없다는 의미이며 전체 기록의 안전 확인이 아니다. 검사기는 파일과 Git 인덱스를 변경하지 않는다.

패턴 검사는 **모든 민감 정보의 검출을 보장하지 않는다**. 오탐·미탐이 가능하며, 문맥 속 비밀번호·개인 정보·알려지지 않은 키 형식은 놓칠 수 있다. 커밋 전 직접 검토가 필요하다. 이 명령은 사용자가 직접 실행하는 검사이며 Git Commit을 자동 차단하는 Hook으로 설치하지 않았다. 검사 없이 커밋하는 것을 기술적으로 막지는 않는다.

- 보류된 대화는 원문이 안전한지 검토하고, 민감 내용을 제거한 수동 공유본을 준비할 수 있다. 이때 `원문 수정본: 민감 정보 제거`임을 본문에 명시하고 원문 그대로 보존한 기록이라고 표시하지 않는다. 기존 기록은 자동 수정하지 않는다.
- `.chat-history/`는 로컬 대기 상태·잠금 관리용이므로 Git에서 계속 제외한다. 탐지하지 못한 민감 값은 이 폴더나 기록 파일에 남을 수 있다. 로컬 접근 권한·백업·동기화 정책의 영향을 받으며 Windows NTFS ACL이나 암호화를 설정하지 않는다.
- 수동 입력 JSON은 기록기가 작성한 파일이 아니므로 검사에서 거절해도 원래 입력 파일에 값이 남는다. 기존 Codex 대화 저장소나 UI에 전달된 내용도 이 기록기가 제거하지 않는다.
- 오류 응답에는 원문이나 예외 상세를 출력하지 않는다. 기록기는 외부로 데이터를 전송하지 않는다. Commit·Push는 사용자가 수행한다.

## 실패 처리와 제한

- 성공은 `{}`, 실패는 원문을 포함하지 않는 `systemMessage` 경고를 JSON으로 반환하고 정상 종료한다. 차단이나 모델 재실행을 요청하지 않는다. Hook 시간 제한은 5초이며 작은 로컬 파일 처리만 수행한다. 런타임 자체의 실행 오류·시간 초과 표시는 이 코드가 제어할 수 없다.
- 잠금 충돌 시 기다리지 않고 경고한다. 충돌한 제출 이벤트는 누락될 수 있고, 충돌한 종료 이벤트는 대기 상태가 남을 수 있다. 자동 재시도·백그라운드 서비스는 없다. 다른 작업을 지연시키지 않기 위한 절충이다.
- 프로세스가 강제 종료되면 `.chat-history/lock`이 남을 수 있다. 실행 중인 기록기가 없음을 확인한 다음 빈 `lock` 디렉터리를 삭제하고 다시 시도한다. 디스크 오류·강제 종료 중에는 불완전한 파일이 남을 수 있다. 자동으로 기존 기록을 수정하지 않는다.
- 중단·취소·오류로 `Stop`이 발생하지 않으면 완성 기록이 만들어지지 않는다. 대기 프롬프트만 남을 수 있다.
- 다른 `Stop` Hook이 모델을 계속 실행시키는 구성에서는 첫 `Stop`의 메시지가 최종 UI 답변과 다를 수 있다. 이 기록기는 나중 이벤트로 기존 파일을 고치지 않는다. 다른 계속 실행 Hook과 함께 쓸 때는 기록 범위를 확인하거나 수동 복사를 사용한다.
- 문자열 필드만 보존한다. 이미지·첨부 파일·도구 출력·중간 진행 메시지·화면 렌더링은 보존하지 않는다. Hook에 IDE 컨텍스트가 포함되는지는 실제 이벤트에 달려 있으며, 입력창의 키 입력을 직접 수집하지 않는다.
- 설정 이전 대화는 소급 수집하지 않는다. 기존 `0001`만 존재하고, 앞선 두 번째 요청이나 이번 요청 전체가 자동 저장되었다고 주장하지 않는다.

## 일시 중지와 대체 방법

기록만 잠시 중지하려면 루트에서 다음을 실행한다. 개발 기능과 다른 Hook은 유지된다.

```powershell
New-Item -ItemType Directory -Force .chat-history
New-Item -ItemType File -Force .chat-history/disabled
```

재개하려면 `.chat-history/disabled` 파일만 삭제한다. 영구 해제는 `.codex/hooks.json`에서 이 기록기의 두 항목을 제거하고 Codex를 다시 시작한다.

자동 수집을 사용할 수 없으면 UI에서 실제 프롬프트와 최종 답변을 복사해 `.chat-history/manual.json`을 UTF-8로 작성한다. 예시 값은 실제 원문으로 교체하며 JSON의 줄바꿈과 따옴표는 정상적으로 이스케이프한다. 아직 생성되지 않은 최종 답변을 만들어 넣지 않는다.

```json
{
  "task": "작업명",
  "prompt": "UI에서 복사한 실제 사용자 프롬프트",
  "response": "UI에서 복사한 실제 최종 답변"
}
```

```powershell
node scripts/chat-history.cjs --manual .chat-history/manual.json
```

이 방식도 기존 번호 다음에 새 파일만 생성하며 `Source: manual-copy`로 표시한다. 동일 파일로 명령을 다시 실행하면 새 기록이 만들어지므로 한 번만 실행한다. 원문을 확인할 수 없다면 기록을 보류한다. 완료 후 입력 JSON은 로컬 민감 자료로 관리한다.
