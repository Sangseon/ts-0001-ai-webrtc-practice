# Step 17 — 화면 구조와 사용자 흐름 확정 설계

## 목적, 근거, 현재 상태

[Concept](./Concept.md)와 [PLAN](./PLAN.md)의 단일 활성 미디어 회의방, 다중 논리 방 소속, 독립적인 채팅 채널을 유지하면서 사용자가 현재 무엇을 보고 어디에 송수신 중인지 알 수 있는 화면을 설계한다. 사용자는 **B안 통합 대시보드와 아래 배치·상태·조작 원칙을 승인**했다. 이는 Step 17 설계 확정이며 Step 18 구현이나 실제 사용성 검증을 뜻하지 않는다.

작업 시작 시 `git status --short`와 `git diff --stat`는 모두 비어 있었다. [README](../README.md), [Step03](./Step03.md)~[Step16](./Step16.md), [QC](./QC.md), [QA](./QA.md), `package.json`, `client/src`와 `server/src/shared/protocol.ts`를 대조했다. 화면은 소스와 [style.css](../client/src/style.css)를 정적으로 확인했다. **실행 중인 화면을 직접 렌더링하거나 모바일 기기에서 확인하지 않았다.** 아래 문제와 배치는 코드·CSS에 근거한 판단 및 제안이며 실제 사용성 검증 결과가 아니다.

현재 [App.tsx](../client/src/App.tsx)는 연결 상태·ID → [MediaPanel](../client/src/MediaPanel.tsx) → 프로필 → [Rooms](../client/src/Rooms.tsx) → [Chat](../client/src/Chat.tsx) → 접속자 순서로 배치하며 상단에 이전 작업인 `Step 11` 문구가 고정돼 있다. [style.css](../client/src/style.css)의 `main` 최대 폭은 `48rem`이고 일반 `form, section`을 같은 테두리 카드로 표시하며 미디어 타일용 화면 그리드와 폭별 배치 규칙은 없다. 기능별 제어가 긴 세로 열에 흩어져, 활성 방·채팅 채널·화면에서 본 방의 차이를 화면 전체에서 비교하기 어렵다. 디버그용 ID·트랙·JSON 통계는 주요 조작과 같은 수준으로 노출된다. 이는 코드에서 확인한 정보 배치 문제이며 실제 사용자 관찰 결과는 아니다.

### 서로 독립인 다섯 내부 상태와 네 가지 주요 표시

| 상태 | 현재 소유자·의미 | 설계에서 보여줄 위치와 동작 |
| --- | --- | --- |
| 논리 방 소속 | `useSession.joinedRooms`; 서버의 방 참가 권한. 여러 방 가능 | 방 목록의 `참여 중` 표식과 참가자 수. 입장·퇴장만 변경 |
| 방 정보 표시 대상 | `useSession.selectedRoomId`; 미가입 방도 목록에서 볼 수 있음 | 왼쪽 방 행·상세 정보의 선택. 가입·채팅·미디어 연결은 변경하지 않으며 일반 화면에서 별도의 `보는 방` 상태로 강조하지 않음 |
| 채팅 채널 | `Chat` 내부 `channel`; 전체 또는 가입 방, 퇴장하면 전체로 복귀 | `전체 채팅 / 가입한 방` 탭. 선택한 채널의 메시지·방 참가자 정보를 같은 우측 영역에 표시하고 그 채널로만 전송. 미디어 불변 |
| 연결 대상 방 | `MediaPanel.target`; 다음 명시적 송신·수신 연결 또는 전환 대상 | **왼쪽** `미디어 연결 대상` 선택과 연결/전환 버튼에 표시. 방 정보 선택·오른쪽 채팅 탭 변경으로 대상이 자동 변경되지 않으며 대상 선택만으로 연결 실행 없음 |
| 실제 활성 미디어 방 | `useSfuSender.activeMediaRoomId`; 실제 연결/연결 시도 방 | 상단·중앙 제목에 `미디어 연결 중: A방`. 중앙 로컬·원격 타일은 이 방 기준으로 유지 |

사용자에게 우선 표시할 네 가지는 **가입한 방, 왼쪽 미디어 연결 대상, 중앙의 실제 활성 미디어 방, 오른쪽 채팅 채널**이다. `selectedRoomId`는 왼쪽 방 상세 정보 표시를 위한 내부 상태로 구분한다. Step 18에서는 방 행의 모호한 `보기` 버튼과 별도 대상 선택기가 중복 조작처럼 보이지 않도록 명칭·배치를 검토하되, 내부 상태를 무조건 병합하지 않는다. `participantId`는 WebSocket 세션마다 새로 부여될 수 있다. 방 이름이 중복될 수 있으므로 목록·진단에는 roomId를 접근 가능하게 남긴다. 오른쪽 채팅을 B로 바꾸거나 왼쪽에서 다음 미디어 대상을 B로 골라도 A 미디어 타일과 A 연결 표시는 유지한다. 미디어 대상만 고르는 행위로 Producer/Consumer를 만들지 않는다.

상태는 현재 `useSession`의 `connecting/connected/disconnected`, `useLocalMedia`의 `idle/requesting/ready/stopping/error`, `useSfuSender`의 `idle/connecting/sending/ready/receiving/stopping/error`와 ICE/Recv 상태, 장치·미터의 loading/전환/분석 상태를 그대로 사용한다. 새 설계가 이 상태들을 합쳐서 잘못된 성공 표시를 만들면 안 된다. 원격 오디오 `play()` 성공은 브라우저 재생 상태이며 실제 사람이 들었다는 증거는 아니다. 서버·브라우저 가상 장치 검증과 물리 인수의 차이는 [Step13](./Step13.md)을 따른다.

## 화면 구조 후보

| 기준 | A. 방 목록 → 입장 준비 → 회의 화면 | B. 통합 대시보드 | C. 방 중심 화면 + 미디어 팝업 |
| --- | --- | --- | --- |
| 이해도·상태 구분 | 순서가 쉽지만 다중 소속·채팅 전환 시 별도 화면 이동 필요 | 내부 다섯 상태를 구분하고 사용자에게 필요한 네 상태를 같은 화면에서 표시 가능 | 방 화면과 미디어 팝업 간 대상 혼동 가능 |
| 주요 기능 접근성 | 입장 전 설정은 좋지만 회의 중 장치·채팅 접근이 멀어질 수 있음 | 방·타일·채팅·제어를 한 화면에서 사용 | 미디어 제어는 빠르나 참가자·채팅을 오가야 함 |
| 데스크톱·좁은 폭 | 여러 단계/라우팅 설계가 필요 | 넓은 폭은 3영역, 좁은 폭은 패널 전환 | 팝업 크기·포커스 관리 부담 |
| 재사용·Step 18 비용 | 화면 전환과 Hook 마운트 유지 설계가 큼 | 현재 App/Rooms/Chat/MediaPanel 재배치와 일부 표시 책임 분리로 시작 가능 | 팝업 생명주기·미디어 참조 분리 부담 |
| 자동화 영향 | 버튼 화면 전환·마운트 변화로 큼 | ID·`data-testid` 유지 시 중간; DOM 위치·텍스트 탐색은 수정 필요 | 창/팝업 탐색 추가로 큼 |

**사용자가 B안, 통합 대시보드를 승인했다.** 현재는 라우터와 별도 입장 전 화면이 없고, 한 세션이 동시에 여러 방 채팅을 볼 수 있다. 대시보드는 이 관계를 지속해서 보이게 하며 기존 Hook의 장기 마운트를 유지하기 쉽다. 장치 준비는 별도 페이지 대신 중앙 미디어 영역 아래의 접는 설정 패널로 둔다. A·C안은 비교 기록으로 남긴다.

### 확정 화면의 정보 배치

```text
┌ 연결: 연결됨 │ 내 프로필 │ 미디어 대상: B │ 미디어 연결 중: A │ 채팅: B │ 종료 ┐
├ 방 목록·생성 ──────────┬ 활성 방 A의 로컬·원격 미디어 타일 ─┬ [채팅] [참가자] ┤
│ A 참여 중 / B 참여 중 │ 원격 B  원격 C / 영상 없음 대체 표시 │ 전체 / A / B 탭   │
│ 방 정보·입장·퇴장     │ 카메라·마이크·미디어 종료            │ B 채팅·B 참가자  │
│ 미디어 대상: B 선택   │ A 영상·음성은 대상 선택만으로 유지    │ B로만 메시지 전송 │
│ [B방으로 미디어 전환] │ 연결 중·오류·원격 재생 재시도        │ 탭 전환은 독립   │
├───────────────┴ 접는 장치 설정·미리보기·마이크 입력 테스트 ┴───────────────┤
└ 오류·복구 안내 / 별도의 접는 연결 진단(ID·Transport·Producer·Consumer·RTP) ┘
```

상단의 `미디어 대상`, `미디어 연결 중`, `채팅`은 **각각 이름과 별도 텍스트 표식**으로 표시한다. 가입 상태는 왼쪽 방 목록에 표시한다. 방 정보 대상은 왼쪽 상세 제목에만 표시하고 일반 화면의 별도 `보는 방` 상태로 강조하지 않는다. 채팅이 B이고 미디어가 A인 경우 중앙 그리드의 제목은 계속 `미디어 연결 중: A방`이다. 왼쪽에서 B를 다음 미디어 대상으로 선택해도 중앙 A 타일과 오른쪽의 기존 채팅 채널은 유지된다. 미디어에 연결하지 않았다면 중앙은 `미디어 미연결`을 표시하고 왼쪽에서 명시적 연결을 시작하게 한다. 방 목록에는 전체 방과 가입 방의 차이를 표시한다. 우측 참가자 패널은 **오른쪽에서 선택한 채팅 방의 참가자**를 보여주며, 중앙 타일은 **활성 미디어 방의 원격 참가자**를 보여준다. 전체 채팅에는 특정 방 참가자 목록을 연결하지 않고 `회의방 미선택` 안내를 표시한다. 전체 접속자 목록은 일반 화면에서 제외하되 기존 수집·동기화는 유지하고 연결 진단에서 확인할 수 있게 한다.

### 확정 채널·참가자 동기화 및 미디어 독립성

우측 채널 탭은 `전체 채팅 | A방 | B방 | …` 형태로 **실제로 가입한 방만** 나열한다. 현재 `Chat`은 `session.rooms`를 필터링하여 옵션을 표시하므로 Step 18에서는 그 배열의 제공 순서를 재사용한다. 별도 정렬 계약은 없으며 생성·입장 순서가 항상 보장된다고 주장하지 않는다. 선택 탭은 텍스트와 `aria-selected` 등 적절한 접근성 상태로 표시하고, 색상만으로 구분하지 않는다.

선택한 채널을 우측 메시지 목록·입력 대상·참가자 패널의 공통 기준으로 사용한다. `전체 채팅`은 전체 메시지를 보여주고 전체로만 전송하며, 참가자 패널은 `회의방 미선택`을 안내한다. 가입한 A/B방 채널은 각각 해당 방 메시지와 `joinedRooms[roomId]` 참가자 목록을 보여주고 그 방으로만 전송한다. 방을 나가거나 채널이 유효하지 않으면 기존 동작처럼 전체 채팅으로 돌아가며, **유효하지 않은 방으로 전송하지 않는다**. 서버의 방 소속 검증도 그대로 유지한다. 패널에서 `채팅`과 `참가자` 보기를 바꿔도 선택 채널과 채팅 초안은 유지한다.

왼쪽 방 정보 선택은 `selectedRoomId`만 변경하고, 왼쪽 **미디어 대상 선택**은 `MediaPanel.target`만 변경한다. 둘 다 우측 `Chat.channel`을 변경하지 않는다. 우측 채널 탭 선택은 우측 채팅/참가자 표시만 바꾸고 왼쪽 방 정보·미디어 대상이나 중앙 타일/SFU 연결을 변경하지 않는다. `selectedRoomId`와 `target`은 현재 별도 상태이므로 Step 18에서는 명확한 `방 정보`와 `미디어 연결 대상` 표현을 우선하고, 중복된 `보기` 조작이 필요한지 검토한다. 두 상태를 무조건 병합하거나 방 정보 선택을 미디어 대상 변경으로 취급하지 않는다. **우측 채팅·참가자만 동일한 유효 `channel`을 참조**하도록 필요한 범위에서 표시 상태를 공유한다. 실제 미디어 연결·전환은 왼쪽의 명시적 버튼에서 `useSfuSender.start`를 호출할 때만 실행한다. 미가입 방이 방 정보에 표시될 수는 있지만 그 방은 미디어 대상 목록에서 선택할 수 없고 연결 버튼은 비활성화하며 `먼저 회의방에 입장하세요`를 안내한다.

## 주요 조작 계약

| 표시 이름(제안) | 활성 조건·비활성 이유 | 실제 동작과 성공·실패 표시 |
| --- | --- | --- |
| `다시 연결` / `연결 종료` | 끊겼을 때 재연결, 연결 중 중복 비활성 | `useSession.reconnect/disconnect`. 새 세션은 새 ID·빈 방 소속이 될 수 있음. 실패는 헤더 오류 |
| `프로필 변경` | 연결됨·저장 중 아님 | 기존 `updateProfile`; 저장 중 표기와 서버 오류 유지 |
| `회의방 생성` | 연결됨·요청 중 아님·유효한 이름 | `createRoom`; 생성자는 자동 입장. 이름 오류를 안내 |
| 방 `정보 보기`(명칭은 Step 18에서 점검) | 방이 목록에 있음 | `setSelectedRoomId`만 호출. 미가입도 정보를 볼 수 있으며 미디어 대상·채팅·활성 연결 불변. 별도 `보기` 버튼 중복 여부 검토 |
| 방 `입장` / `퇴장` | 입장은 미가입, 퇴장은 가입; 연결됨·요청 중 아님 | `joinRoom/leaveRoom`; 활성 미디어 방 퇴장만 그 미디어 종료. 다른 방 소속 보존 |
| 왼쪽 `미디어 연결 대상` | 연결됨·가입 방을 대상 목록에 노출; 미가입 방은 연결 조작 비활성 | `MediaPanel.target`만 선택. 미가입 방에는 `먼저 회의방에 입장하세요` 표시. 우측 채팅 채널과 중앙 활성 연결은 유지 |
| `로컬 미디어 시작` / `로컬 미디어 종료` | 카메라/마이크 하나 이상 선택·요청 상태 확인 | `useLocalMedia.start/stop`. 종료는 현재 MediaPanel처럼 SFU 종료도 연계; 실패·권한 대기 표시 |
| 왼쪽 `선택 방에 송신·수신 연결` | 연결됨·가입 방·로컬 준비 완료·전환 중 아님 | `sender.start(target)`; 성공 후 활성 방 갱신. 오른쪽 채팅은 불변. 실제 연결 전 `연결 중`, 실패 시 오류 |
| 왼쪽 `선택 방 수신만 연결` | 연결됨·가입 방·전환 중 아님; 로컬 미디어 불필요 | `sender.start(target,true)`; Producer 없이 원격 구독. 오른쪽 채팅은 불변. 실패·자동 재생 대기 표시 |
| 왼쪽 `B방으로 미디어 전환` | 활성 A와 대상 B가 다르고 대상 가입·필요한 로컬 준비 완료; 전환 중 중복 조작 비활성 | 기존 `useSfuSender.start` 경로로 A 자원을 먼저 종료하고 B 연결. 버튼 옆에 `A 연결을 종료하고 B로 전환`을 명시. 실패 시 실제 활성 상태·오류와 이전 A 연결이 이미 닫혔을 수 있음을 표시. 두 방의 논리 소속과 오른쪽 채팅 채널은 불변 |
| `미디어 연결 종료` | 활성 연결/시도가 있음 | `sender.stop`; 로컬 트랙과 논리 방·채팅은 유지 |
| `카메라 끄기` / `카메라 켜기` | 송신 연결·해당 처리 중 아님 | 기존 `cameraOff/cameraOn`; OFF의 Track·Producer 종료와 ON의 재획득을 상태별로 안내 |
| `마이크 음소거` / `음소거 해제` | Audio Producer 있는 송신 연결·처리 중 아님 | `setMicrophoneMuted`; 서버 확인 전 처리 중, 오류 시 실제 안전한 음소거 표시. 수신 전용은 비활성 |
| 장치 선택 / `선택 장치 적용` | 목록 선택은 언제나 별도. 적용은 live 트랙·유효 장치·전환 중 아님 | 선택만으로 획득/송신하지 않음. `switchDevice` 성공 뒤 `실제 사용` 변경, 실패 시 오류와 기존 상태 |
| `장치 목록 새로고침` | 브라우저 지원 시 | `devices.refresh`; 권한 요청 없이 목록 상태 갱신 |
| `마이크 테스트 시작` / `종료` / `분석 재개` | 기존 미터 상태 기준 | `useMicrophoneMeter`; 상대 레벨 표시, 회의 음소거 불변, 테스트 전용 트랙만 정리 |
| `원격 음성/영상 재생` | 타일 트랙·재생 대기 또는 수동 재시도 | `RemoteMedia.Playback.play`; Promise 성공/거절을 타일에 표시, 사람의 청취 성공으로 표시하지 않음 |
| `전체 채팅 / 가입한 방` 탭·`채팅/참가자` 보기 / `메시지 전송` | 채널은 전체 또는 가입 방; 전송은 연결됨·유효 메시지·요청 중 아님 | 선택 채널의 메시지·방 참가자를 함께 표시하고 선택 채널로만 전송. 전체 채팅의 참가자 보기는 `회의방 미선택` 안내. 서버 권한·길이·프로필·내역·오류 규칙 유지 |

현재 코드에 없는 **새로운 UI 표현**은 가입 상태와 왼쪽 미디어 대상·중앙 활성 방·오른쪽 채팅 채널의 구분 표시, 채널별 채팅·참가자 연동, 서로 분리된 접는 장치 설정/연결 진단, 좁은 화면의 패널 선택, 전환 경고 문구다. 프로토콜·서버 기능은 새로 필요하지 않다. 확인 대화상자나 자동 전환·자동 장치 획득·자동 재연결은 확정 설계에 넣지 않았다. Step 18에서 상태 공유 범위와 실제 동작 보존을 검증해야 한다.

| 채팅 B·활성 미디어 A | 상단 둘 다 표시; 우측 B 메시지·B 참가자, 중앙 타일은 A. B 채팅 전송만 B로 전달, A 미디어 종료 없음 |
| 왼쪽 대상 B·채팅 A·활성 미디어 A | 왼쪽은 다음 연결 대상 B, 중앙은 기존 A 타일, 오른쪽은 A 채팅·A 참가자. 버튼 클릭 전 SFU 변화 없음 |

| 권한 거부·장치 없음·장치 분리 | 장치 종류별 오류·현재 실제 트랙·명시적 재시도. 목록 변경만으로 다른 장치를 자동 획득하지 않음 |

| 활성 방 퇴장 / 다른 방 퇴장 | 활성 방 퇴장은 미디어 종료·타일 정리. 다른 방 퇴장은 미디어 유지. 둘 다 연결 자체는 유지 |

**기본 흐름:** 접속 → 연결 상태·ID 확인 → 프로필 설정 → 방 생성/입장 → 원하는 A/V 종류와 장치 선택 → `로컬 미디어 시작`으로 권한·미리보기 → 가입 방을 미디어 대상으로 선택 → 명시적으로 송신·수신 또는 수신만 연결 → 타일/채팅 이용 → 카메라·마이크 제어 → `미디어 연결 종료` 또는 방 퇴장. 로컬 미디어 획득 전에도 방과 채팅을 이용할 수 있고 수신만 연결할 수 있다.

**다중 방 흐름:** A·B 모두 입장 → 왼쪽에서 A를 미디어 대상으로 선택해 연결 → 오른쪽 B 채팅 탭 선택 → 우측 B 채팅·B 참가자, 중앙 A 미디어 유지 → 왼쪽 다음 대상을 B로 선택해도 오른쪽 B 채팅과 중앙 A 미디어 유지 → `B방으로 미디어 전환` 명시 → A 자원 종료, B 연결 성공 뒤 중앙 B 미디어, 오른쪽 채팅은 B 또는 그 전에 선택한 채널을 그대로 유지 → A 논리 소속과 채팅 사용 가능 상태 유지. 채팅 채널을 `selectedRoomId`나 `target`과 기술적으로 합치지 않는다.

**오류 흐름:** WebSocket 실패는 헤더 오류와 `다시 연결`; 새 연결의 participantId·방 소속을 새로 확인하고 자동 미디어 송신은 하지 않는다. 권한 거부·장치 부재·늦은 획득은 로컬 설정의 실패/대기 안내 후 사용자 재시도. SFU 실패는 중앙 미디어 오류와 재연결 조작, 로컬 트랙·채팅은 실제 상태대로 별도 표시. 자동 재생 거절은 타일별 버튼으로 재시도한다. 사용 장치 제거는 목록·트랙 상태를 다시 보게 하고 자동 대체하지 않는다. 처리 중 중복 클릭은 기존 비활성·Hook 가드에 따른다. 새로고침은 새 WebSocket 세션과 명시적 재입장을 요구한다.

### 독립성을 확인할 대표 시나리오

**A — 영상회의 중 다른 방 채팅:** ① A·B방에 논리적으로 가입한다. ② 왼쪽에서 A방을 미디어 대상으로 선택하고 명시적으로 송수신을 시작한다. ③ 중앙에서 A방 로컬·원격 미디어를 확인한다. ④ 오른쪽 B방 탭을 선택해 B방 채팅과 B방 참가자를 확인하고 B방으로만 메시지를 전송한다. ⑤ 오른쪽 A방 탭으로 돌아온다. 전 과정에서 중앙 A방 영상·음성과 왼쪽 미디어 대상 A는 유지된다.

**B — 미디어 연결 대상만 변경:** ① A방 미디어 연결 중 오른쪽 B방 채팅을 연다. ② 왼쪽에서 다음 미디어 대상 B를 선택한다. ③ 중앙은 A방 미디어, 오른쪽은 B방 채팅·참가자를 그대로 표시하며 실제 전환은 일어나지 않는다. ④ 왼쪽 `B방으로 미디어 전환` 버튼을 누르면 기존 A방 자원을 종료하고 B방 연결을 시작한다. ⑤ 성공 후 중앙만 B방 미디어를 표시한다. 오른쪽 채팅 채널은 자동으로 바꾸지 않는다.

**C — 미디어 전환 후 기존 채팅 유지:** ① 오른쪽 A방 채팅을 선택한다. ② 왼쪽에서 B방을 대상으로 정하고 명시적으로 전환한다. ③ 중앙 미디어는 성공 후 B방으로 바뀌지만 오른쪽 채팅·참가자는 A방을 유지한다. ④ 오른쪽 B방 탭을 따로 선택해야 B방 메시지·참가자 표시와 전송 대상으로 변경된다.

**D — 전체 채팅:** ① A방 미디어 연결 중 오른쪽 `전체 채팅`을 선택한다. ② 전체 메시지를 확인하거나 전체로만 전송한다. ③ 오른쪽 참가자 보기는 `회의방 미선택`을 안내한다. ④ 중앙 A방 미디어와 왼쪽 미디어 대상은 그대로 유지된다.

## 데스크톱·좁은 폭·접근성 제안

현재 CSS에는 breakpoint가 없다. 아래 폭은 Step 18에서 실제 렌더와 키보드 검증을 거쳐 조정할 **초안**이다. 모바일의 물리 장치·브라우저 WebRTC 동작을 확인했다는 의미가 아니다.

| 768~1199px | 방 목록은 접는 패널, 중앙 타일 1~2열, 우측 채팅·참가자 보기 전환. 활성 미디어 배지는 항상 상단 |

영상 없는 참가자는 아바타·이름·`카메라 OFF/미사용`을 표시한다. 오류는 색뿐 아니라 문장과 복구 버튼으로 알린다. 키보드 순서는 헤더 연결/프로필 → 방 선택/입장 → 미디어 타일·재생 → 송수신 제어 → 채팅 → 설정·진단 순서로 제안한다. 선택 채널 탭에는 `aria-selected` 등 실제 탭 패턴에 맞는 접근성 상태와 텍스트 이름을 제공한다. 접는 패널은 버튼의 `aria-expanded`와 제목을 제공하고 열린 패널의 첫 조작으로 포커스를 이동한다. 아이콘만 쓰는 버튼에는 의미 있는 접근 가능한 이름, `:focus-visible`에 선명한 테두리를 둔다. 연결·오류는 `role=status/alert`, 송신·음소거 상태는 시각 표식과 텍스트를 함께 쓰며 레벨 미터에는 수치/설명을 유지한다. 패널 전환은 UI 표시만 바꾸며, 방 목록·참가자 패널·장치 설정을 열거나 닫아도 WebRTC 연결·트랙·Producer/Consumer·AudioContext 분석 루프의 기존 생명주기를 바꾸지 않는다.

모든 QA 기능은 설계상 접근 가능하다. 다만 기존 QA의 버튼 이름·위치를 그대로 사용할 수 있는지 여부는 Step 18의 최종 문구에 달려 있다. Step 18에서 QA 절차의 조작 문구와 자동화 선택자를 실제 UI에 맞춰 별도 갱신할 필요가 있다. **QA 판정과 증거는 지금 바꾸지 않는다.**

사용자가 위 화면 구조와 조작 원칙을 승인했다. **Step 17 완료 당시 상태는 `설계 승인·완료 (Step 18 구현 대기)`**였다. 후보 비교·기존 코드 분석·QA-001~026 정적 대응은 설계 근거로 유지한다. 실제 반응형 크기, 채널 상태 공유 방식, 접는 패널의 마운트 방식, 선택자 영향은 Step 18 구현·회귀 검증 대상이었다. React·CSS·Hook·프로토콜·테스트 코드는 Step 17에서 변경하지 않았으며 실제 UI·수동 QA가 통과했다는 뜻은 아니다. 이후 Step 18의 구현·자동화 회귀를 마치고 프로젝트 개발을 종료했다. 사용자 수동 인수는 수행하지 않았다.
